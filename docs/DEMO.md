# สคริปต์สาธิต — การขายและการชำระเงินครบวงจร (ส่วนของ B)

ใช้ซ้อมก่อนนำเสนอ และเปิดดูระหว่างนำเสนอ ลำดับนี้เป็นลำดับเดียวกับเทสต์ `e2e/b/demo-rehearsal.spec.ts`
ถ้าเทสต์นี้ผ่าน การสาธิตจริงจะเดินได้ครบทุกขั้น

ใช้เวลาประมาณ 8–10 นาที · ข้อมูลร้าน ลูกค้า และรหัสพร้อมเพย์ในระบบเป็นข้อมูลสมมติทั้งหมด

## ก่อนขึ้นนำเสนอ (เช้าวันนำเสนอ)

1. ตรวจว่าเว็บใช้ฐานข้อมูลที่ seed ใหม่ และตั้งค่า `SHOW_DEMO_ACCOUNTS=true`, `PAYMENT_WEBHOOK_SECRET`, `CRON_SECRET` แล้ว
2. รันเทสต์ซ้อมกับเว็บที่จะใช้จริง ต้องผ่านทั้ง 2 ข้อ:
   ```bash
   E2E_BASE_URL=https://<โดเมน> PAYMENT_WEBHOOK_SECRET=<ค่าเดียวกับบน Vercel> npx playwright test e2e/b/demo-rehearsal.spec.ts
   ```
3. ตรวจความถูกต้องของข้อมูล ต้องได้ 0 แถว: `psql "$DATABASE_URL" -f scripts/integrity.sql`
4. เปิดแท็บรอไว้ 2 แท็บ: แท็บหน้าร้าน `/demo-shop` และแท็บหลังร้าน (login `wiphada` / 1234)
5. **แผนสำรอง:** ถ้าเน็ตหรือเว็บมีปัญหา ให้เปิดวิดีโอที่อัดจากเทสต์ซ้อมแทน
   ```bash
   DEMO_VIDEO=1 npx playwright test e2e/b/demo-rehearsal.spec.ts -g "order → QR"   # วิดีโออยู่ใน test-results/**/video.webm
   ```

## คำถามที่น่าจะโดนถาม

**ทำไมไม่ใช้ระบบชำระเงินจริง** — ผู้ให้บริการรับชำระเงินต้องจดทะเบียนร้านค้าเชิงพาณิชย์ จึงทำโหมดเดโมให้ขั้นตอนเหมือนจริงทุกขั้น
QR ทำตามมาตรฐาน ระบบรอ webhook ตรวจลายเซ็น และตรวจยอดเงิน · ถ้าจะใช้จริง แค่เพิ่มตัวเชื่อมผู้ให้บริการจริง (เช่น Opn Payments) ที่ส่ง webhook แบบเดียวกัน
หน้าอื่นไม่ต้องแก้ (`src/server/payments/`)

**ถ้าลูกค้าสองคนกดซื้อชิ้นสุดท้ายพร้อมกัน** — การจองใช้คำสั่ง `UPDATE … WHERE qty − reserved >= n` คำสั่งเดียว ฐานข้อมูลยอมให้คนเดียวผ่าน
อีกคนได้ข้อความ "เหลือไม่พอ" · ฐานข้อมูลมี CHECK ซ้อนอีกชั้นว่า 0 ≤ reserved ≤ qty · มีเทสต์ยืนยันทั้งกรณีสต็อกและสิทธิ์คูปองชิ้นสุดท้าย

**คนอื่นยิง webhook ปลอมมาได้ไหม** — ไม่ได้ ต้องมีลายเซ็น HMAC-SHA256 จากคีย์ลับที่อยู่บนเซิร์ฟเวอร์เท่านั้น
ลายเซ็นผูกกับเวลา (ส่งซ้ำได้ภายใน 5 นาที) · ใช้ eventId กันการประมวลผลซ้ำ · ยอดเงินต้องตรงกับคำสั่งซื้อ · มีเทสต์ทุกกรณีนี้

**ถ้าลูกค้าไม่จ่ายเงิน** — ครบ 15 นาทีระบบยกเลิกคำสั่งซื้อ คืนสต็อกที่จอง และคืนสิทธิ์คูปอง
ระบบตรวจตอนมีคนสั่งซื้อใหม่ ตอนเปิดหน้าจ่ายเงิน ตอนเปิดหลังร้าน และ Cron รายวัน
ถ้าเงินเข้ามาหลังหมดเวลา ระบบไม่ตัดสต็อก และขึ้นในแท็บ "ต้องคืนเงิน" จนกว่าจะบันทึกการโอนคืน

**ข้อมูลหายหรือคำนวณผิดจะรู้ได้อย่างไร** — สำรองข้อมูลทุกคืนแบบเข้ารหัส และกู้ไฟล์สำรองลงฐานข้อมูลชั่วคราวเพื่อตรวจทุกครั้งก่อนเก็บ
กฎที่ตรวจ (`scripts/integrity.sql`):
- ยอดจอง = ออเดอร์ที่รอจ่าย
- ออเดอร์ที่รับเงินแล้วมี Payment ตรงยอด 1 รายการ
- Serial บนชั้น = สต็อก + ของที่จ่ายแล้วแต่ยังไม่ส่ง
- สิทธิ์คูปองที่ใช้ = จำนวนออเดอร์ที่ใช้คูปองนั้น

กฎชุดเดียวกันรันเป็นเทสต์ทุก PR ด้วย

**กำไรคิดอย่างไร** — (ยอดสินค้าหลังหักส่วนลด ÷ 1.07) − ต้นทุนที่บันทึกไว้ตอนขาย
ถ้าแก้ราคาทุนภายหลัง กำไรของออเดอร์เก่าไม่เปลี่ยน · ค่าส่งแสดงแยก ไม่นับเป็นกำไรสินค้า

## ต่อยอดให้ใช้งานจริง

- ต่อผู้ให้บริการชำระเงินจริงที่ `src/server/payments/` และตั้ง `PROMPTPAY_ID` ของร้านจริง
- ตั้ง Cron ทุก 5 นาที (ต้องใช้ Vercel Pro) หรือใช้ตัวตั้งเวลาภายนอกเรียก `/api/cron/expire-orders`
- ใส่ข้อมูลบริษัทจริงใน `src/lib/shop.ts` (ใบเสร็จ/ใบกำกับภาษี) และปิด `SHOW_DEMO_ACCOUNTS`
